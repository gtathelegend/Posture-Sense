# PostureSense v2 — Session Persistence & Analytics Pipeline Specification

## 1. Session Lifecycle Architecture

The PostureSense v2 perception pipeline records user exercise telemetry locally in the browser and persists finalized summaries to Supabase PostgreSQL upon session completion:

```text
Browser Engines (Camera -> MediaPipe -> Landmark -> Biomechanics -> Pose -> Movement -> Scoring -> Feedback)
    ↓
Session Telemetry Harvesting (templates/app.html)
    ↓
JSON Session Summary Payload (savePoseSession)
    ↓
POST /save_pose_session (Flask API Endpoint with current_user.id binding)
    ↓
SessionService.save_session() (Parameter Validation: 0-100 ranges, non-negative numbers, nulls)
    ↓
SessionRepository.create_session() (SQL Insert via Supabase Client)
    ↓
Supabase PostgreSQL (public.pose_sessions table)
    ↓
AnalyticsRepository & DashboardService (Non-NULL Aggregations & Longitudinal Trends)
    ↓
Dashboard V2 UI / API Reports / PDF Exports
```

## 3. Database Schema (`public.pose_sessions`)

Migration SQL: `migrations/001_rich_session_persistence.sql`

```sql
CREATE TABLE IF NOT EXISTS public.pose_sessions (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id uuid NOT NULL REFERENCES public.users (id) ON DELETE CASCADE,
    pose_label text NOT NULL,
    timestamp timestamptz NOT NULL DEFAULT timezone('utc', now()),
    duration double precision NOT NULL DEFAULT 0,
    accuracy double precision NOT NULL DEFAULT 0,
    reps integer NOT NULL DEFAULT 0,
    symmetry_score double precision NULL,
    balance_score double precision NULL,
    stability_score double precision NULL,
    rom_score double precision NULL,
    hold_time double precision NOT NULL DEFAULT 0.0,
    tracking_quality double precision NULL,
    failed_rules jsonb NOT NULL DEFAULT '[]'::jsonb
);
```

### Critical Data Rule — `NULL` vs `100.0`
- `symmetry_score`, `balance_score`, `stability_score`, `rom_score`, and `tracking_quality` default to `NULL` (unmeasured).
- `NULL` explicitly means *"Metric was not available for this session"*.
- Metric values are **never** filled with artificial defaults (`100.0` or `0.0`).

## 4. Backend Validation Rules

Location: `backend/app/services/session_service.py`

| Field | Type | Validation Constraint | Rejection Response |
| :--- | :--- | :--- | :--- |
| `user_id` | String / UUID | Derived strictly from `current_user.id` | 401 Unauthorized if unauthenticated |
| `pose_label` | String | Non-empty string, excluding `"Scanning..."` | 400 Bad Request (`Invalid pose label`) |
| `duration` | Float | $\ge 0.0$ | 400 Bad Request (`Duration cannot be negative`) |
| `accuracy` / `overall_score` | Float | $0.0 \le \text{val} \le 100.0$ | 400 Bad Request (`Accuracy score must be between 0 and 100`) |
| `reps` | Integer | $\ge 0$ | 400 Bad Request (`Reps cannot be negative`) |
| `symmetry_score` | Optional Float | $0.0 \le \text{val} \le 100.0$ or `NULL` | 400 Bad Request (`Symmetry score must be between 0 and 100`) |
| `balance_score` | Optional Float | $0.0 \le \text{val} \le 100.0$ or `NULL` | 400 Bad Request (`Balance score must be between 0 and 100`) |
| `stability_score` | Optional Float | $0.0 \le \text{val} \le 100.0$ or `NULL` | 400 Bad Request (`Stability score must be between 0 and 100`) |
| `rom_score` | Optional Float | $0.0 \le \text{val} \le 100.0$ or `NULL` | 400 Bad Request (`ROM score must be between 0 and 100`) |
| `hold_time` | Float | $\ge 0.0$ | 400 Bad Request (`Hold time cannot be negative`) |
| `tracking_quality` | Optional Float | $0.0 \le \text{val} \le 100.0$ or `NULL` | 400 Bad Request (`Tracking quality must be between 0 and 100`) |
| `failed_rules` | List | JSON array of strings or dicts | 400 Bad Request (`Failed rules must be a list`) |

## 5. Security & User Isolation Boundaries

1. **Authentication Enforcement:** `@login_required` decorator wraps all API endpoints (`POST /save_pose_session`, `GET /api/analytics/*`, `GET /api/reports/*`).
2. **Strict User Binding:** Client payloads cannot overwrite `user_id`. The backend assigns `user_id = current_user.id`.
3. **Cross-User Data Isolation:** Queries explicitly filter by `.eq('user_id', str(current_user.id))`. User A cannot query, view, or modify User B's sessions or analytics.
4. **Zero Media/Landmark Persistence:** Camera streams, canvas renders, and 33 3D landmark array coordinates remain strictly local to the user's browser memory and are **never** transmitted to the server.
